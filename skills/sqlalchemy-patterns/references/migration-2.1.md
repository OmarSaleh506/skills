# Upgrading from SQLAlchemy 2.0 to 2.1

SQLAlchemy 2.1 is released (2.1.x on PyPI as of October 2026). Everything in this skill works on both 2.0 and 2.1 unless marked. The items below are the 2.1 changes most likely to affect an async + PostgreSQL codebase. Source: "What's New in SQLAlchemy 2.1?" (`https://docs.sqlalchemy.org/en/21/changelog/migration_21.html`).

## Install / environment

| Change | Action |
|---|---|
| Python ≥ 3.11 required | Upgrade the interpreter before the library |
| `greenlet` no longer installed by default | Depend on `sqlalchemy[asyncio]`, not bare `sqlalchemy` |
| Default PG driver is psycopg 3 (`postgresql://` → `psycopg`) | Always spell the driver: `postgresql+asyncpg://` or `postgresql+psycopg://` |

## ORM behavior

- **Autoflush is unconditional** — the session flushes before every execution, including Core statements and `text()`. Pending objects are now visible to raw SQL in the same transaction; code that relied on them *not* being flushed must change.
- **Loader-option path rule** — when one object is loaded through several paths in a query, the shallowest path's options apply to later loads (deterministic; 2.0 was not). See `loading.md`.
- **Dataclass mappings (`MappedAsDataclass`)** — omitted constructor arguments are no longer written into `__dict__` (a `DONT_SET` sentinel is used); defaults are delivered via descriptors. Fixes the 2.0 bug where `Parent(related_id=5)` with `related: ... = relationship(default=None)` inserted NULL. If your code inspected `obj.__dict__` for defaults, re-test it.
- **Session-level execution options** — `Session` / `AsyncSession` / `async_sessionmaker(..., execution_options={...})` apply to queries *and* flushes (e.g. `schema_translate_map` for multi-tenant schemas).
- `relationship(back_populates=...)` accepts a callable.

## Core / typing

- `Row` / `Result` / `Select` are typed per column without `Tuple`: `Select[int, str]`, `Row[int, str]` (mypy ≥ 1.7). Drop `Row._t` workarounds.
- `select().filter_by()` searches all FROM entities and raises `AmbiguousColumnError` on ambiguous names — switch those to `.where(Entity.col == v)`.
- `ClauseElement.params()` / `unique_params()` are deprecated in favor of the new executable-level `params()`.
- New: `tstring()` (Python 3.14 t-strings) as a safer `text()`; `CreateView` / `CreateTableAs` DDL constructs.

## PostgreSQL

- Named types (ENUM, DOMAIN) belong to `MetaData`, inherit its schema, and `Table.drop()` no longer drops them; `inherit_schema` is deprecated. See `postgresql.md` § 7.
- `Computed(...)` renders VIRTUAL by default (PostgreSQL 18 semantics) — add `persisted=True` to keep STORED columns, and check autogenerated migrations.
- Server-side monotonic functions such as `func.uuidv7(monotonic=True)` work as sentinels in batched INSERT..RETURNING.
- `DELETE ... USING` is supported explicitly.

## Upgrade checklist

1. Pin `sqlalchemy[asyncio]>=2.1,<2.2` and make sure Python ≥ 3.11.
2. Make every DB URL name its driver.
3. Run the test suite with `-W error::DeprecationWarning` (or SQLAlchemy's `SADeprecationWarning`) to surface deprecated calls.
4. Grep for `Computed(` without `persisted=` and for `filter_by(` after joins.
5. If you use `MappedAsDataclass`, re-test object construction with FK-only arguments.
6. Run `alembic check` — named-type and computed-column changes can show up as diffs.
